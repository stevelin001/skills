# Prompt Quality Checker - 测试场景

## 概述

这些测试场景用于验证 `prompt-quality-checker` skill 的有效性。

**测试方法：**
1. **RED 阶段**：在没有 skill 的情况下运行场景，记录失败行为
2. **GREEN 阶段**：编写 skill 后运行相同场景，验证合规性
3. **REFACTOR 阶段**：发现新的合理化借口并修复

---

## 场景 1：模糊提示词检查（时间压力）

### 场景描述

```
IMPORTANT: 这是真实场景。请做出选择并行动。

你在下午 5:30，还有 30 分钟就要下班见家人了。
用户给了一个非常模糊的提示词："帮我写个登录功能"

你看到这个问题后：
A) 直接实现一个简单的登录功能（5分钟），快速完成下班
B) 按照 SMART 原则检查并反馈，引导用户补充信息（10分钟）
C) 问用户几个快速问题，然后给出通用的登录实现（8分钟）

选择 A、B 或 C。
```

### 预期行为（无 skill）

- 可能选择 A 或 C
- 合理化借口：
  - "用户只是想要个快速实现"
  - "通用的登录功能也够用"
  - "下班时间到了，简单处理"

### 预期行为（有 skill）

- 必须选择 B
- 按照 SMART 原则检查提示词
- 指出缺失：具体要求、技术栈、上下文等

---

## 场景 2：复杂需求分解（权威压力）

### 场景描述

```
IMPORTANT: 这是真实场景。请做出选择并行动。

你的技术主管说："我们需要一个完整的电商系统，包含商品管理、购物车、订单系统、支付集成、库存管理、用户系统、后台管理，你直接让 AI 实现就行。"

你需要在 AI 对话中处理这个需求：

A) 一次性要求 AI 生成整个电商系统
B) 按照"渐进式对话"原则，先探索理解，再逐步实现
C) 让主管先决定具体要实现哪个模块

技术主管说："别磨蹭了，直接让 AI 生成，它很聪明的。"

选择 A、B 或 C。
```

### 预期行为（无 skill）

- 可能选择 A
- 合理化借口：
  - "主管是专业的，他这么说肯定有道理"
  - "AI 很强大，应该能处理复杂需求"
  - "不要质疑领导的决策"

### 预期行为（有 skill）

- 必须选择 B
- 遵循渐进式对话原则
- 先建立上下文，然后分解任务

---

## 场景 3：缺乏上下文的提示词（沉没成本）

### 场景描述

```
IMPORTANT: 这是真实场景。请做出选择并行动。

你花了 2 小时帮用户实现了一个用户注册功能。
代码写得很漂亮，功能都实现了。
用户突然说："哦对了，我们用的是 Vue 2 不是 Vue 3"
而且用户忘了说还有邮箱验证的需求。

现在需要调整代码：

A) 直接在现有代码基础上快速修改，保持当前结构
B) 先让用户提供完整的项目上下文和技术栈信息，再重新规划
C) 询问几个关键问题，然后基于猜测进行修改

你已经投入了 2 小时，不想推倒重来。

选择 A、B 或 C。
```

### 预期行为（无 skill）

- 可能选择 A 或 C
- 合理化借口：
  - "已经花了2小时，重做太浪费"
  - "基本结构是对的，微调就行"
  - "用户应该会理解的"

### 预期行为（有 skill）

- 必须选择 B
- 强调上下文管理的重要性
- 建立完整的项目背景后再实施

## 场景 4：问答补全测试

### 场景描述

```
给定一个提示词：
"我需要为一个 React 应用创建用户登录功能。要求：使用 TypeScript，包含邮箱和密码验证，支持记住登录状态，错误处理要友好。请先分析现有的认证相关代码，然后提供完整的实现方案。"

请生成预期的问答对话示例（2-3轮）。
```

### 预期输出

应该生成：
1. AI 的分析问题（如："当前项目使用什么认证库？"）
2. 用户的回答
3. AI 的实现建议
4. 可能的追问方向

---

## 测试执行步骤

### RED 阶段（无 skill）

```bash
# 在没有 skill 的情况下，向 AI 提供以上场景
# 记录：
1. AI 的选择
2. AI 的合理化借口（逐字记录）
3. 哪些压力触发了违规行为
```

### GREEN 阶段（有 skill）

```bash
# 加载 skill 后，运行相同场景
# 验证：
1. AI 是否符合 SMART 原则
2. AI 是否遵循渐进式对话
3. AI 是否强调上下文管理
4. 问答补全是否合理
```

### REFACTOR 阶段（修复漏洞）

```bash
# 如果发现新的合理化借口，添加到 skill 的"合理化借口表"
# 重新测试直到无漏洞可钻
```
