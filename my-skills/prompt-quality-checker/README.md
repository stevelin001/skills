# Prompt Quality Checker - 使用示例

## 快速开始

这个 skill 可以帮助你：

1. **检查提示词质量** - 评估提示词是否符合 SMART 原则
2. **编写高质量提示词** - 引导你创建结构化的提示词
3. **生成问答示例** - 基于提示词预览对话流程

---

## 示例 1：检查模糊提示词

### 用户输入

```
帮我检查这个提示词怎么样：
"帮我写个登录功能"
```

### AI 响应（使用 skill 后）

```
## 提示词质量评估

### 符合度评分
- Specific (具体性): ⭐☆☆☆☆ (1/5) - 未说明技术栈、框架、具体需求
- Measurable (可衡量): ⭐☆☆☆☆ (1/5) - 无明确的验证标准
- Achievable (可达成): ⭐⭐☆☆☆ (2/5) - "登录功能"范围不明确
- Relevant (相关性): ⭐☆☆☆☆ (1/5) - 缺少项目上下文
- Time-bound (时限性): ⭐☆☆☆☆ (1/5) - 无阶段划分

**总体评分：** ⭐☆☆☆☆ (1.2/5) - 需要大幅改进

### 主要问题
1. 未说明使用什么技术栈（React/Vue/原生？）
2. 未说明需要哪些登录方式（邮箱密码？第三方？）
3. 未说明项目背景和现有代码结构
4. 无明确的验收标准

### 改进建议
1. 添加项目类型和技术栈信息
2. 明确具体的登录需求和功能
3. 提供项目上下文和编码规范
4. 分步骤描述期望的实现流程

### 优化后的提示词
```
我需要为一个 React 应用创建用户登录功能。

**背景信息：**
- 项目使用 TypeScript 和 Next.js 14
- 已有基础的认证中间件（位于 /middleware/auth.ts）
- UI 组件基于 shadcn/ui 和 Tailwind CSS
- 后端使用 Prisma + PostgreSQL

**具体要求：**
- 邮箱和密码登录
- 支持记住登录状态（使用 httpOnly cookie）
- 友好的错误处理（显示具体错误信息）
- 遵循项目现有的组件结构

**期望输出：**
1. 先分析 /middleware/auth.ts 的现有实现
2. 提供完整的前端登录页面组件
3. 提供对应的 API 路由实现
4. 包含类型定义和错误处理
```

## 示例 2：辅助编写提示词

### 用户输入

```
我需要给 AI 一个提示词，实现博客的评论功能，但我不知道怎么写才好。
```

### AI 响应（使用 skill 后）

```
## 编写高质量提示词

我会引导你按照 SMART 原则构建一个优秀的提示词。

### 第一步：项目背景
请提供以下信息：

1. **项目类型：** （例如：Next.js 博客、WordPress 插件、原生 JS）
2. **技术栈：** （例如：React + TypeScript + Tailwind）
3. **现有功能：** （例如：已有文章展示、用户认证）
4. **参考代码：** （例如：现有的其他组件路径）

### 第二步：明确需求
关于评论功能，请明确：

1. **基础功能：** 发表评论、删除评论、编辑评论？
2. **高级功能：** 评论回复、点赞、举报、敏感词过滤？
3. **实时性：** 是否需要实时更新（WebSocket）？
4. **格式支持：** 是否支持 Markdown、表情、链接？

### 第三步：编码规范
1. 项目使用什么代码风格（Prettier/ESLint 配置）？
2. 组件命名约定是什么？
3. 错误处理如何实现（Toast/Alert/Inline）？

---

**请逐条回答以上问题，我会为你生成一个结构化的提示词。**
```

## 示例 3：生成问答示例

### 用户输入

```
基于以下提示词，生成预期的问答对话：
"我需要为一个 React 应用创建用户登录功能。要求：使用 TypeScript，包含邮箱和密码验证，支持记住登录状态，错误处理要友好。请先分析现有的认证相关代码，然后提供完整的实现方案。"
```

### AI 响应（使用 skill 后）

```
## 预期对话流程

### 第一轮：AI 分析与澄清

**AI 可能的提问：**

1. **技术栈确认：**
   - "项目使用哪个版本的 React？"
   - "状态管理使用什么方案（Redux/Zustand/Context）？"
   - "路由方案是 React Router v5 还是 v6？"

2. **认证方案：**
   - "是否已有后端 API？使用什么认证方案（JWT/Session）？"
   - "是否需要集成第三方登录（Google/GitHub）？"

3. **代码结构：**
   - "能否提供项目目录结构或现有组件的路径？"
   - "是否有现有的认证相关代码可以参考？"

### 第二轮：用户补充

**用户可能的回答：**
```
React 18 + Vite，使用 Context API 做状态管理。
后端已有 /api/auth/login 接口，返回 JWT token。
项目结构在 /src，组件在 /src/components。
目前没有认证相关代码，这是第一个功能。
```

### 第三轮：AI 实现方案

**AI 的响应：**
```
## 实现方案

基于你的需求，我会创建以下文件：

1. **类型定义** (`src/types/auth.ts`)
   - User, LoginCredentials, AuthResponse 类型

2. **认证 Context** (`src/contexts/AuthContext.tsx`)
   - AuthProvider 组件
   - useAuth 自定义 Hook

3. **登录组件** (`src/components/LoginForm.tsx`)
   - 表单验证
   - 错误处理
   - 记住状态逻辑

4. **工具函数** (`src/utils/auth.ts`)
   - token 存储管理
   - 登录/登出 API 调用

是否需要我逐步实现这些文件？
```

### 可能的后续追问方向

1. **安全性相关：**
   - "是否需要添加 CSRF 保护？"
   - "Token 刷新机制如何处理？"

2. **用户体验：**
   - "登录成功后跳转到哪里？"
   - "是否需要'忘记密码'功能？"

3. **测试相关：**
   - "需要编写单元测试吗？使用哪个测试框架？"

4. **部署相关：**
   - "环境变量如何配置？"
   - "是否有生产环境的特殊要求？"
```
